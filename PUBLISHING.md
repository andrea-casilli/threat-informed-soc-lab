# Publication Checklist

Use this checklist before creating the public GitHub repository or a release.

- [x] README explains purpose, safety boundary, setup, usage, validation, and roadmap.
- [x] MIT license, contribution guidance, security policy, and code of conduct are present.
- [x] CI runs linting, typing, tests, validation, and secret scanning.
- [x] Generated build artifacts, virtual environments, local logs, and `.env` files are ignored.
- [x] Validation evidence is retained in `reports/coverage-report.md` and `mitre/coverage.json`.
- [ ] Replace `<your-repository-url>` in the README after creating the GitHub repository.
- [ ] Add a repository description: `Safe, reproducible threat-informed SOC detection engineering lab.`
- [ ] Add topics: `soc`, `blue-team`, `detection-engineering`, `mitre-attack`, `sigma`, `python`, `cybersecurity`.
- [ ] Enable GitHub Actions and Dependabot/security alerts in repository settings.
- [ ] Review the staged diff and run the quality commands in the README before the first commit.
